# Paystack Payment Operations

## Required server configuration

The Netlify environment must provide:

- `PAYSTACK_SECRET_KEY` — the server-side Paystack secret key. Never expose this through `VITE_*` variables or browser code.
- `PUBLIC_APP_URL` — the canonical HTTPS origin used to construct payment callbacks.

## Webhook registration

Register this HTTPS endpoint in the Paystack dashboard as the integration webhook URL:

`https://<your-public-domain>/.netlify/functions/paystack-webhook`

The webhook validates Paystack's `x-paystack-signature` using HMAC-SHA512 and `PAYSTACK_SECRET_KEY` before processing the event.

## Events handled

The webhook processes `charge.success`. Other Paystack events are acknowledged without changing tuition records.

## Payment integrity rules

A successful transaction is recorded only when all of the following agree with the server-side plan table:

- Paystack reports `success`.
- Currency is `NGN`.
- The transaction amount exactly matches the expected plan amount in kobo.
- The plan ID is known.
- The role is allowed for that plan.
- The metadata contains the authenticated portal user ID used to initialize the transaction.
- An enrollment-linked transaction uses the `parent` role and references an enrollment request owned by that same parent.

## Idempotency and consistency

New verified payments use the Paystack transaction reference as the deterministic Firestore payment document ID. This prevents duplicate records during concurrent callback/webhook delivery.

Payment creation and enrollment `paymentStatus` updates are performed together in a Firestore transaction. A failure cannot leave a newly-created payment marked paid while the linked enrollment remains unpaid.

Existing legacy payment documents that were created with autogenerated Firestore IDs remain supported by the verification fallback query.

## Customer return flow

The portal callback still calls `paystack-verify` so the customer receives immediate confirmation after returning from checkout. The webhook is the independent server-side reconciliation path and must not depend on the customer returning to the browser.

## Deployment checklist

After deploying to production:

1. Confirm `PAYSTACK_SECRET_KEY` is set in the Netlify production environment.
2. Confirm `PUBLIC_APP_URL` resolves to the production origin with HTTPS.
3. Register the webhook URL in Paystack.
4. Make a controlled test transaction in the correct Paystack environment.
5. Confirm a `charge.success` event reaches the webhook and the matching `payments/{reference}` document is created.
6. For an enrollment-linked payment, confirm the exact `enrollment_requests/{id}` document changes to `paymentStatus: "PAID"`.
7. Re-deliver the same webhook/test callback and confirm no duplicate payment document is created.
8. Review Netlify function logs for rejected signatures, metadata mismatches, or enrollment ownership mismatches.
